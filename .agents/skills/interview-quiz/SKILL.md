# Interview Quiz

这是一个面向当前知识库的面试抽查流程。默认读取工作区根目录下的 `c++interview/` 和 `llm-algo-leetcode/`，不得修改、移动或删除其中任何文件。

## Invocation

- 用户调用 `$interview-quiz`（或明确说“面试抽查”）时启动一轮。
- 用户调用 `$interview-quiz review` 时只进行到期错题复习，不新建完整题单。
- 用户可指定题数、主题或难度；未指定时生成 10 题，覆盖两个知识源，并尽量混合概念题、代码阅读题、复杂度/设计取舍题。

## Quiz workflow

1. 先检查两个知识源的目录和相关文件，优先使用 Markdown、README、源码注释及可读的 notebook 文本；题目必须能回溯到具体文件路径。
2. 读取 `interview-review/` 下的复习数据（不存在时创建），优先抽取已到期错题，再用未覆盖主题补足本轮题数。
3. 一次只提出一道题，不提前展示标准答案。等待用户回答后，再给出：判定（正确/部分正确/错误）、简短依据、来源路径、改进要点，然后继续下一题。
4. 允许用户说“跳过”“结束”；结束时仍保存已经回答的题目，并汇总得分、薄弱主题和下一次复习日期。
5. 一轮结束后更新 `interview-review/wrong-answers.md`、`interview-review/review-schedule.md` 和 `interview-review/sessions/YYYY-MM-DD.md`。这些文件是派生资料，不得回写两个知识源。

## Evaluation rules

- 正确：核心结论、关键条件和复杂度/边界基本准确。
- 部分正确：方向正确但遗漏关键条件、实现细节或复杂度；进入错题集但保留已掌握部分。
- 错误：结论相反、无法解释，或代码/算法在关键边界失败；进入错题集并从最短间隔重新复习。
- 不确定或来源冲突时，明确标记“待核实”，列出不同来源，不擅自补写事实。
- 不把模型补充的通用知识伪装成项目事实；项目事实必须附来源路径。

## Review data

按需读取 [references/review-schema.md](references/review-schema.md)，遵循其中的字段和遗忘曲线间隔。错题复习到期后，先让用户回忆再展示解析；复习结果更新下一次日期。

默认间隔为：答错/跳过 `1 天`，答对一次 `3 天`，连续答对后依次为 `7、14、30 天`。用户明确要求其他节奏时，以用户设置为准并记录在复习计划中。

## Output style

- 题目短而明确，标注主题和来源文件，但不泄露答案。
- 反馈聚焦回答本身，避免泛泛讲课。
- 每轮结束提供可执行的最小复习清单；不要自动创建外部提醒或修改原始仓库。
